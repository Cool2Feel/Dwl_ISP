# 崩溃日志功能测试指南

## 测试准备

1. 编译项目（确保所有修改都已正确编译）
2. 以 Release 模式运行程序（模拟用户环境）

## 测试场景

### 测试 1: UI线程异常捕获

**目的**：验证UI线程异常能否被正确捕获和记录

**步骤**：
1. 在 Debug 模式下运行程序
2. 在任意位置触发一个UI异常（如：点击一个未实现的按钮）
3. 观察程序行为

**预期结果**：
- ✅ 程序不崩溃，继续运行
- ✅ 弹出错误提示对话框
- ✅ 日志文件中记录了异常详情
- ✅ 可以通过"文件 → 查看崩溃日志"查看

**验证方法**：
```
打开 logs/ThunderSE_YYYY-MM-DD.log 文件
搜索 "[CRASH REPORT]" 或 "Unhandled Dispatcher Exception"
```

---

### 测试 2: 非UI线程异常捕获

**目的**：验证后台线程异常能否被记录

**步骤**：
1. 创建一个后台任务（如：设备连接）
2. 在后台任务中触发异常
3. 观察程序行为

**预期结果**：
- ✅ 程序可能崩溃（这是正常的）
- ✅ 崩溃前记录了详细的异常信息
- ✅ 显示了友好的错误提示
- ✅ 日志文件中包含完整的崩溃报告

**验证方法**：
```
1. 查看日志文件最后的内容
2. 应该能看到格式化的崩溃报告，包含：
   - 系统信息
   - 异常类型和消息
   - 完整堆栈跟踪
   - 加载的程序集列表
```

---

### 测试 3: Task异常捕获

**目的**：验证未观察到的Task异常能否被处理

**步骤**：
在代码中添加以下测试代码（临时）：

```csharp
// 在某个按钮点击事件中
Task.Run(() => {
    throw new InvalidOperationException("测试Task异常");
});
// 不await或.Result，让异常成为未观察到的
```

**预期结果**：
- ✅ 异常被TaskScheduler捕获
- ✅ 程序不崩溃
- ✅ 日志中记录了异常信息

---

### 测试 4: 崩溃日志查看器

**目的**：验证崩溃日志窗口功能正常

**步骤**：
1. 打开程序
2. 点击菜单：**文件 → 查看崩溃日志**
3. 观察窗口是否打开

**预期结果**：
- ✅ 窗口成功打开
- ✅ 显示最新的日志内容
- ✅ 如果有崩溃报告，优先显示崩溃报告部分
- ✅ 窗口标题显示日志文件名

**功能测试**：
- 点击"📋 复制日志" → 应该提示复制成功
- 点击"📂 打开日志目录" → 应该打开logs文件夹
- 点击"❌ 关闭" → 窗口关闭

---

### 测试 5: 日志文件轮转

**目的**：验证日志按日期分割

**步骤**：
1. 修改系统日期到明天
2. 重新启动程序
3. 检查是否创建了新的日志文件

**预期结果**：
- ✅ 创建了新的日志文件：`ThunderSE_YYYY-MM-DD.log`（明天的日期）
- ✅ 旧的日志文件仍然存在
- ✅ 程序写入新的日志文件

---

### 测试 6: 菜单项功能

**目的**：验证新增的菜单项都能正常工作

**测试项**：

#### 开发者模式
1. **文件 → 查看崩溃日志** → 打开日志窗口
2. **文件 → 退出** → 程序退出

2. **文件 → 保存到文件** → 保存文件对话框
3. **文件 → 查看崩溃日志** → 打开日志窗口
4. **文件 → 退出** → 程序退出

## 常见问题排查

### 问题1: 日志文件没有生成

**可能原因**：
- 程序目录没有写入权限
- Logger初始化失败

**解决方法**：
1. 检查程序是否有管理员权限
2. 查看Visual Studio的Debug输出窗口
3. 手动创建logs文件夹并赋予写入权限

### 问题2: 崩溃日志窗口打不开

**可能原因**：
- CrashLogWindow未编译
- XAML文件未添加到项目

**解决方法**：
1. 检查ThunderSE.csproj是否包含CrashLogWindow
2. 重新编译项目
3. 查看是否有编译错误

### 问题3: 异常没有被捕获

**可能原因**：
- 异常处理器注册失败
- 异常发生在注册之前

**解决方法**：
1. 确认RegisterGlobalExceptionHandlers()被调用
2. 查看日志中的"Global exception handlers registered."消息
3. 检查是否有更早的异常发生
