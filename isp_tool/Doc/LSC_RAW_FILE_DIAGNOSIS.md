# LSC Raw 文件大小不匹配问题诊断与修复

## 问题描述

加载 Raw 文件时出现错误提示：
```
文件大小(1382400)与分辨率(921600)不匹配
```

---

## 问题诊断

### 数据分析

- **文件大小**: 1,382,400 字节
- **预期大小**: 921,600 字节（基于当前配置的分辨率）
- **比例**: 1,382,400 / 921,600 = **1.5 倍**

### 可能原因

#### 原因 1：Raw 格式位深不匹配 ⭐ 最可能

**当前配置期望**: 8-bit Raw（每像素 1 字节）
**实际文件**: 10-bit Raw（每像素存储为 2 字节，但有效值 0-1023）

计算验证：
```
921,600 像素 × 1 字节/像素 = 921,600 字节   (8-bit)
921,600 像素 × 2 字节/像素 = 1,843,200 字节 (10/16-bit) ❌

或者：
691,200 像素 × 2 字节/像素 = 1,382,400 字节 ✅
```

**推断实际分辨率**: 1,382,400 / 2 = 691,200 像素
- 可能是 **960×720** (4:3)
- 可能是 **1280×540** (21:9)
- 可能是其他组合

**如何判断是 10-bit 还是 16-bit**：
```
系统会自动采样检测：
- 如果所有像素值 ≤ 1023 → 10-bit Raw ✅
- 如果有像素值 > 1023 → 16-bit Raw
```

#### 原因 2：分辨率配置错误

当前配置的分辨率可能不正确：
```
921,600 = 960 × 960 或 1280 × 720 或 1920 × 480 等
```

#### 原因 3：文件包含额外数据

Raw 文件可能包含：
- 文件头信息（前缀字节）
- 元数据（后缀字节）
- 多帧数据

## 自动诊断功能

### 已实现的智能检测

修改后的 `LoadRawFile()` 方法现在会自动：

1. **检测位深**：判断是 8-bit 还是 16-bit Raw
2. **匹配常见分辨率**：尝试匹配标准分辨率列表
3. **推断分辨率**：根据 16:9 或 4:3 比例计算
4. **提示用户**：显示诊断结果并询问是否自动调整

### 诊断流程

```

  ↓

  ↓
不匹配？

  │        ↓

  │      用户选择：是/否
  │        ├─ 是 → 自动调整分辨率 ✅
  │        └─ 否 → 取消加载
  │
  └─ 否 → 正常加载 ✅
```

### 方案 1：使用自动诊断（推荐）✅

---

### 方案 2：手动调整分辨率

如果自动诊断未识别出正确分辨率：

**步骤**：
1. 计算实际像素数：
   ```
   如果是 16-bit Raw: 像素数 = 文件大小 / 2
   如果是 8-bit Raw:  像素数 = 文件大小
   ```

2. 确定宽高：
   ```
   常见 16:9: 1280×720, 1920×1080, 2560×1440
   常见 4:3:  640×480, 800×600, 1024×768
   ```

3. 在应用程序中手动设置：
   ```
   打开"通用配置"或"CommonConfig"窗口
   修改 ResolutionWidth 和 ResolutionHeight
   保存配置
   ```

---

## 技术细节

### Raw 文件格式说明

#### 8-bit Bayer Raw
```
每像素 1 字节 (0-255)
动态范围：256 级
排列方式：
R G R G R G ...
G B G B G B ...
R G R G R G ...
...
```

#### 10-bit Bayer Raw ⭐ 最常见
```
每像素存储为 2 字节（16-bit 空间），小端字节序
有效值范围：0-1023 (2^10)
动态范围：1024 级
实际占用：文件大小 = 像素数 × 2 字节

示例：
像素值 0x03FF (1023) 存储为：FF 03
像素值 0x0000 (0)   存储为：00 00
```

#### 16-bit Bayer Raw
```
每像素 2 字节 (0-65535)，小端字节序
动态范围：65536 级
排列方式相同，但精度更高
```

### 计算示例

**您的文件**: 1,382,400 字节

假设 10-bit（最可能）：
```
像素数 = 1,382,400 / 2 = 691,200
```

可能分辨率：
```
960 × 720 = 691,200 ✅ (4:3) ← 最可能
1280 × 540 = 691,200 ✅ (21:9)
896 × 771 ≈ 691,200 (非标准)
```

## 常见问题

### Q1: 为什么我的 Raw 文件是 16-bit？

**A**: 大多数专业相机和传感器输出 16-bit Raw，以保留更多细节和动态范围。

### Q2: 我需要转换为 8-bit 吗？

**A**: 不需要。修改后的代码支持自动检测和配置调整。

### Q3: 自动检测失败怎么办？

**A**: 
1. 确认 Raw 文件格式（联系相机/传感器厂商）
2. 手动计算分辨率
3. 在配置中手动设置

### Q4: 修改分辨率后会影响其他模块吗？

**A**: 是的，分辨率是全局配置。所有 ISP 模块（AWB、Gamma 等）都会使用新分辨率。
