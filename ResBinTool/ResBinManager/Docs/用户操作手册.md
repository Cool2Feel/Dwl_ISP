## 1. 软件简介

### 什么是 SDK 资源管理器？

SDK 资源管理器（ResBinManager）是一个用于修改固件资源的桌面工具软件。简单来说，它可以帮助您：

- 📦 **查看**：打开固件文件，查看里面包含的所有资源（图片、声音、字体等）
- 🔄 **替换**：用新的文件替换固件中的资源
- 💾 **保存**：保存修改后的固件文件

### 软件用途

这款软件主要用于嵌入式设备的固件开发和定制，例如：

- 更换设备的开机Logo
- 更新设备的界面图片
- 修改设备的提示音
- 更换设备的显示字体

### 支持的文件类型

| 文件类型 | 说明 |
|---------|------|
| `DestBin.bin` | 完整的固件文件（包含代码和资源） |
| `RES.BIN` | 仅包含资源的文件 |
| `firmware.bin` / `ax329x_sdk.bin` | 其他常见的固件文件格式 |

### 界面各部分说明

#### 工具栏（顶部）

## 3. 基本操作流程

使用本软件的基本流程如下：

#### 资源修改流程

```
1. 打开固件文件 (DestBin.bin / RES.BIN)
       ↓
2. 在资源列表中选择要修改的资源
       ↓
3. 预览资源（确认是要修改的内容）
       ↓
4. 点击"替换"按钮，选择新文件
       ↓
5. 确认替换
       ↓
6. 点击"保存"按钮保存修改
       ↓
7. 将修改后的固件烧录到设备
```

#### 配置修改流程

```
1. 打开 DestBin.bin 固件文件
       ↓
2. 选择项目类型（如 HM020F）
       ↓
3. 点击"⚙️ 加载配置"按钮
       ↓
4. 软件自动解析固件中的配置区
       ↓
   ├─ 配置区有效 → 直接加载配置项
   └─ 配置区空白 → 选择加载方式：
        ├─ 是：加载默认配置（Default_Config.xml）
        ├─ 否：从 XML 配置文件加载
        └─ 取消：保持空白
       ↓
5. 在配置面板中编辑配置项
       ↓
6. 点击"💾 保存配置"按钮保存到固件
```

#### 配置生成流程

```
1. 点击"🗏 生成配置"按钮
       ↓
2. 选择固件项目根目录（包含 config.c、config.h 等文件）
       ↓
3. 软件自动扫描并解析源码文件
       ↓
   解析内容包括：
   • config.c — 配置项定义
   • config.h — 配置头文件
   • 菜单文件 — 菜单选项（如有）
   • user_str.h — 用户字符串定义
   • customer.h / version.h — 客户/版本信息
       ↓
4. 验证配置项（检查重复、越界、未知名称等）
       ↓
5. 选择输出格式（XML 或 JSON）
       ↓
6. 生成配置文件并保存到指定位置
```

## 4. 详细功能操作

### 4.1 打开文件

#### 操作步骤：

1. 点击工具栏上的 **📂 打开** 按钮
   ![](https://trae-api-cn.mchost.guru/api/ide/v1/text_to_image?prompt=Windows%20WPF%20application%20toolbar%20with%20open%20button%20highlighted%20in%20blue%2C%20clean%20UI%2C%20modern%20style&image_size=landscape_4_3)
2. 在弹出的文件选择窗口中：
   - 找到固件文件所在的文件夹
   - 选择 `.bin` 格式的文件（如 `DestBin.bin` 或 `RES.BIN`）
   - 点击 **打开**
   ![](https://trae-api-cn.mchost.guru/api/ide/v1/text_to_image?prompt=Windows%20file%20open%20dialog%20showing%20firmware%20bin%20files%2C%20user%20selecting%20DestBin.bin&image_size=landscape_4_3)
3. 等待软件加载文件（状态栏会显示"Loading file..."）
4. 加载完成后会弹出成功提示，显示资源总数和文件大小
   ![](https://trae-api-cn.mchost.guru/api/ide/v1/text_to_image?prompt=Success%20dialog%20box%20showing%20resource%20loading%20completed%2C%20showing%20total%20resources%20count&image_size=portrait_4_3)

#### 提示：

- 软件会自动识别文件类型，无需手动选择
- 如果打开的是完整固件（DestBin.bin），软件会自动提取其中的资源
- 如果找不到文件，请检查文件路径是否正确

### 4.2 替换资源

#### 操作步骤：

1. 在资源列表中点击选中要替换的资源
   ![](https://trae-api-cn.mchost.guru/api/ide/v1/text_to_image?prompt=Resource%20list%20DataGrid%20with%20one%20resource%20selected%20highlighted%20in%20blue%2C%20showing%20ID%20name%20type%20status%20columns&image_size=landscape_4_3)
2. 点击以下位置之一的 **替换** 按钮：
   - 工具栏上的 **🔄 替换** 按钮
   - 预览面板中的 **替换** 按钮
   - 右键菜单中的 **替换** 选项
3. 在弹出的文件选择窗口中：
   - 找到新文件所在的文件夹
   - 选择与原资源类型匹配的文件（如图片选 `.jpg`，音频选 `.wav`）
   - 点击 **打开**
4. 如果新文件大小与原文件不同，会弹出确认提示：
   - **文件变大**：可能会影响其他资源，需要确认
   - **文件变小**：剩余空间会自动填充，不影响其他资源
   ![](https://trae-api-cn.mchost.guru/api/ide/v1/text_to_image?prompt=File%20size%20warning%20dialog%20box%20showing%20original%20and%20new%20file%20size%2C%20asking%20user%20to%20confirm%20replacement&image_size=portrait_4_3)
5. 点击 **是** 完成替换
6. 资源列表中的状态会变为橙色的"已修改"

#### 提示：

- 替换前建议先预览资源，确认选择正确
- 替换后可以随时点击"恢复"按钮撤销修改
- 字体资源需要特殊处理，请参考第5.3节

### 4.3 保存文件

#### 操作步骤：

1. 完成资源替换后，点击工具栏上的 **💾 保存** 按钮
2. 在弹出的对话框中选择保存方式：
   - **覆盖（是）**：直接替换原文件，同时自动创建备份
   - **另存为（否）**：保存为新文件，原文件保持不变
   - **取消**：取消保存操作
   ![](https://trae-api-cn.mchost.guru/api/ide/v1/text_to_image?prompt=Save%20dialog%20box%20asking%20user%20to%20choose%20overwrite%20or%20save%20as%2C%20Windows%20style&image_size=portrait_4_3)
3. 如果选择"另存为"，需要选择保存位置和文件名
4. 保存完成后会弹出成功提示

#### 两种保存方式的区别：

| 方式 | 优点 | 缺点 |
|------|------|------|
| 覆盖 | 操作简单，自动备份 | 原文件被替换 |
| 另存为 | 原文件不受影响 | 需要手动选择保存位置 |

### 4.4 导出资源

#### 操作步骤：

1. 在资源列表中选中要导出的资源
2. 点击以下位置之一的 **导出** 按钮：
   - 预览面板中的 **导出** 按钮
   - 右键菜单中的 **导出** 选项
3. 在弹出的保存对话框中：
   - 选择保存位置
   - 输入文件名（软件会自动推荐合适的文件名）
   - 点击 **保存**

#### 提示：

- 导出功能可以帮助您提取固件中的资源进行查看和分析
- 导出的文件可以作为替换时的参考

### 4.5 恢复原始

#### 操作步骤：

1. 在资源列表中选中已修改的资源（状态显示为橙色"已修改"）
2. 点击预览面板中的 **恢复** 按钮（橙色按钮）
3. 在弹出的确认对话框中点击 **是**
4. 资源会恢复到修改前的状态

#### 提示：

- 恢复功能仅在资源被修改后可用
- 恢复操作不需要保存，关闭软件后重新打开会恢复到原始状态
- 如果已经保存了修改，恢复仅影响当前会话

### 4.6 配置加载

配置加载功能允许您从固件文件中读取配置参数，或从 XML 配置文件加载配置。加载后可以在配置面板中编辑并保存回固件。

#### 前提条件：

- 必须先打开 **DestBin.bin** 格式的固件文件（非 RES.BIN）
- 固件文件必须包含有效的配置区

#### 操作步骤：

1. 打开 DestBin.bin 固件文件
2. 在工具栏点击 **⚙️ 加载配置** 按钮
3. 软件会自动解析固件中的配置区，可能出现以下情况：

##### 情况一：配置区有效

- 软件直接加载配置项，状态栏显示"配置加载成功"
- 配置面板自动显示在界面底部
- 可直接编辑配置项

##### 情况二：配置区为空白或无效

弹出"配置区空白"对话框，提供三种处理方式：

| 选项 | 说明 |
|------|------|
| **是 (Y)** | 加载默认配置（基于内置 Default_Config.xml） |
| **否 (N)** | 从外部 XML 配置文件加载 |
| **取消** | 保持空白配置，不进行任何加载 |

##### 方式一：加载默认配置

1. 在对话框中点击 **是**
2. 软件从内置资源 `Default_Config.xml` 加载默认配置
3. 加载完成后配置面板显示所有默认配置项
4. 可在此基础上进行修改

##### 方式二：从 XML 配置文件加载

1. 在对话框中点击 **否**
2. 在弹出的文件选择对话框中，选择 XML 配置文件（默认打开 `config` 目录）
3. 软件解析并验证 XML 配置文件
4. 如果验证发现问题（如索引越界、重复项、未知名称等），会弹出警告
5. 确认后加载配置项到配置面板

#### 通过"Load XML"按钮加载

如果已加载配置但需要从另一个 XML 文件重新加载：

1. 在配置面板中点击 **Load XML** 按钮
2. 选择 XML 配置文件
3. 软件会验证并加载配置项（会替换当前配置）

#### 提示：

- 配置加载仅在 **DestBin 模式** 下可用
- 如果提示"请先打开 DestBin.bin 文件"，请确认打开的文件类型
- 加载 XML 配置时，文件需符合 `ConfigXmlParser` 规定的格式
- 配置修改后需点击 **保存配置** 按钮才能写入固件

### 4.7 配置生成

配置生成功能允许您从固件项目的源代码文件自动解析并生成配置映射文件（XML 或 JSON 格式）。

#### 适用场景：

- 新项目初始化时生成配置映射
- 源码中的配置项有更新时重新生成
- 为其他工具或系统提供配置数据

#### 操作步骤：

1. 在工具栏点击 **🗏 生成配置** 按钮
2. 在弹出的文件夹选择对话框中，选择固件项目的根目录（包含 `config.c` 的目录）
3. 软件会自动在该目录下搜索以下文件：

| 文件 | 说明 | 必需 |
|------|------|------|
| `config.c` | 配置项定义文件 | ✅ 必需 |
| `config.h` | 配置头文件 | 可选 |
| 菜单文件 | 菜单项定义 | 可选 |
| `user_str.h` | 用户字符串定义 | 可选 |
| `customer.h` | 客户信息 | 可选 |
| `version.h` | 版本信息 | 可选 |

4. 如果找不到 `config.c` 文件，会提示错误并终止

5. 在弹出的"保存配置文件"对话框中：
   - 选择保存位置
   - 输入文件名（默认 `Project_Config`）
   - 选择输出格式：
     - **XML 文件 (\*.xml)**：包含完整配置项和菜单信息
     - **JSON 文件 (\*.json)**：仅包含配置项映射

6. 软件开始解析源码，状态栏显示"正在解析源码..."

7. 解析完成后会显示验证结果，可能的验证警告包括：
   - **重复索引**：多个配置项使用了相同的索引
   - **索引越界**：配置项索引超出有效范围 `[0, SDK_CONFIG_ID_MAX)`
   - **未知名称**：配置项名称未在 `ConfigId` 枚举中定义

8. 如果有警告，会询问是否继续生成。选择"是"将过滤掉无效项后继续

9. 生成完成后弹出成功提示，显示：
   - 生成的文件路径
   - 提取的配置项数量
   - （如有）解析的菜单选项数量

#### 提示：

- XML 格式包含更完整的信息（含菜单），JSON 格式仅包含配置映射
- 生成的配置文件可用于"配置加载"功能中的 XML 加载方式
- 建议将生成的配置文件放入项目的 `config` 目录中统一管理
- 如果多次生成，注意不要覆盖已有的配置文件

## 5. 配置功能详解

### 5.1 配置面板介绍

加载配置后，界面底部会显示配置编辑面板，包含以下区域：

| 区域 | 说明 |
|------|------|
| 项目类型 | 选择固件对应的项目型号（如 HM020F） |
| 配置模板 | 选择配置方案模板（不同方案有不同的配置项定义） |
| Config Address | 配置在固件中的存储地址（只读，十六进制显示） |
| Config Status | 配置有效性状态：Valid（绿色）/ Invalid（红色） |
| Refresh 按钮 | 刷新配置显示，同步界面编辑到配置数据 |
| Load XML 按钮 | 从 XML 配置文件加载配置（会替换当前配置） |
| 配置项列表 | 以表格形式展示所有配置项，支持直接编辑 |

### 5.2 配置模板选择

通过配置模板下拉菜单可以切换不同的配置方案：

- 不同的模板定义了不同的配置项集合
- 切换模板会重新加载该方案下的配置项
- 建议选择与当前固件匹配的模板

### 5.3 配置项编辑

配置项列表以表格形式展示，支持以下操作：

| 列 | 说明 |
|------|------|
| ID | 配置项索引（只读） |
| 名称 | 配置项名称（如 BACKLIGHT、BEEP_EN） |
| 类型 | 配置项类型（Numeric、Enum、Boolean 等） |
| 值 | 当前值，可直接编辑 |
| 选项 | 根据类型显示可选值 |
| 起始位 | 在配置标志中的起始位置 |
| 位长度 | 占用的位宽 |

#### 编辑操作：

1. 直接点击单元格进行编辑
2. Enum 类型的配置项提供下拉选择框
3. Numeric 类型的配置项可直接输入数值
4. 修改后状态栏会提示"Configuration modified"

### 5.4 保存配置到固件

编辑完成后，需要将配置保存回固件：

1. 点击工具栏的 **💾 保存配置** 按钮
2. 软件会自动：
   - 将界面修改同步到内部数据
   - 备份原始固件文件（`.config_backup-时间戳`）
   - 应用资源修改到固件（如有）
   - 将配置数据写入固件的配置区
3. 保存成功后弹出提示，显示备份文件名

#### 注意：

- 保存操作会同时处理资源修改和配置修改
- 保存后建议使用"加载配置"按钮重新加载以验证修改
- 备份文件包含配置修改前的固件状态，可用于恢复

## 6. 特殊资源处理

### 6.1 图片资源

图片资源包括 JPEG、BMP 等格式：

- **预览**：选中后会在预览面板中显示图片
- **替换**：可以使用同类型的图片文件替换
- **注意**：
  - 建议保持图片尺寸一致，避免显示异常
  - 文件大小变化会影响其他资源位置

### 6.2 音频资源

音频资源为 WAV 格式：

- **预览**：选中后会显示音频信息（时长、采样率等）
- **播放**：可以点击"播放"按钮试听音频
- **替换**：使用 WAV 格式的音频文件替换
- **音量控制**：可以调整播放音量

### 6.3 字体资源 ⚠️ 特殊处理

字体资源包含两个文件（`resfont.bin` 和 `resfontidx.bin`），必须一起替换：

#### 操作步骤：

1. 在资源列表中选择任意一个字体资源
2. 常规的"替换"按钮会被禁用
3. 在右侧预览面板中找到 **字体预览** 区域
4. 点击绿色的 **🔄 替换字体** 按钮
5. 在弹出的对话框中同时选择 `resfont.bin` 和 `resfontidx.bin` 两个文件
6. 点击 **确定** 完成替换

**重要提示**：
- 必须同时选择两个文件，否则无法替换
- 两个文件必须匹配（来自同一套字体）
- 单独替换其中一个会导致字体显示异常

### 6.4 调色板资源

调色板资源定义了设备使用的颜色：

- **预览**：显示调色板中的所有颜色
- **替换**：使用新的调色板文件替换
- **注意**：调色板会影响所有使用该调色板的图片显示

## 7. 常见问题解答

### Q1: 打开文件时提示"Failed to load file"怎么办？

**原因**：文件格式不正确或文件已损坏

**解决方法**：
- 确认文件是有效的固件文件（`.bin` 格式）
- 检查文件是否完整，尝试重新获取文件
- 确认文件没有被其他程序占用

### Q2: 替换资源时提示"Invalid resource file"怎么办？

**原因**：替换文件格式不正确或与原资源类型不匹配

**解决方法**：
- 检查替换文件的格式是否正确（如图片用 `.jpg`，音频用 `.wav`）
- 确认文件没有损坏
- 尝试使用其他同类文件替换

### Q3: 替换字体资源时找不到"替换字体"按钮？

**原因**：没有选中字体资源或字体资源未被正确识别

**解决方法**：
- 确保选中的是 `resfont.bin` 或 `resfontidx.bin` 文件
- 检查资源列表中是否有这两个文件
- 如果仍然找不到，请联系技术支持

### Q4: 保存时提示"Save failed"怎么办？

**原因**：文件权限不足或磁盘空间不足

**解决方法**：
- 尝试以管理员身份运行软件
- 检查目标文件夹是否有写入权限
- 确认磁盘有足够的空间

### Q5: 修改后的资源如何恢复？

**方法**：
- 在资源列表中选中已修改的资源
- 点击预览面板中的"恢复"按钮
- 在确认对话框中点击"是"

**注意**：如果已经保存了文件，恢复操作只在当前会话有效，关闭软件后修改仍然存在。

### Q6: 替换资源后文件大小变化会有什么影响？

**影响**：
- **新文件更大**：会向后移动所有后续资源，可能影响资源偏移
- **新文件更小**：剩余空间会用固定数据填充，不影响其他资源

**建议**：
- 尽量保持文件大小一致
- 如果必须改变大小，请确认后续资源不受影响

### Q7: 点击"加载配置"按钮提示"请先打开 DestBin.bin 文件"怎么办？

**原因**：当前打开的文件不是 DestBin.bin 格式，或文件尚未打开

**解决方法**：
- 确认已打开 DestBin.bin 文件（而非 RES.BIN）
- 在软件标题栏检查当前模式是否为 DestBin 模式
- 重新打开正确格式的固件文件

### Q8: 配置加载后配置区显示为 Invalid 怎么办？

**原因**：固件中的配置区数据无效、损坏或为空

**解决方法**：
- 使用"加载配置"功能，在提示时选择"是"加载默认配置
- 或选择"否"从 XML 配置文件加载
- 如果是首次使用，建议加载默认配置作为起点

### Q9: 配置生成时提示"未找到 config.c 文件"怎么办？

**原因**：选择的目录不正确，或项目结构与标准固件项目不同

**解决方法**：
- 确认选择的是固件项目的根目录（包含 config.c 的目录）
- 检查 config.c 文件是否存在于 firmware 子目录中
- 如果项目结构特殊，请手动导航到包含 config.c 的目录

### Q10: 配置生成验证警告怎么处理？

**常见警告**：
- **重复索引**：多个配置项使用了相同的索引编号
- **索引越界**：配置项索引超出有效范围
- **未知名称**：配置项名称未在枚举中定义

**处理方法**：
- 如果确认这些警告是预期内的（如测试配置），点击"是"继续生成
- 如果不确定，点击"否"取消，检查源码后重试
- 生成的文件会自动过滤掉无效项

### Q11: XML 配置文件加载验证失败怎么办？

**原因**：XML 文件格式不正确，或包含无效的配置项

**解决方法**：
- 检查 XML 文件格式是否正确（参考 Default_Config.xml 模板）
- 确认配置项索引在有效范围内 [0, SDK_CONFIG_ID_MAX)
- 检查是否有重复的索引值
- 使用"生成配置"功能从源码重新生成一份有效的配置文件

## 8. 注意事项

### 操作前注意

1. **备份原文件**：在修改前建议手动备份原固件文件
2. **确认资源类型**：替换前确认资源类型和新文件类型一致
3. **测试修改**：修改后建议先在测试设备上验证效果
4. **确认项目类型**：加载配置前请选择正确的项目类型

### 操作中注意

1. **不要同时修改多个文件**：建议一次只修改一个资源并保存
2. **注意文件大小**：过大的文件可能导致固件空间不足
3. **字体资源特殊处理**：必须同时替换 `resfont.bin` 和 `resfontidx.bin`
4. **配置修改谨慎**：配置参数直接影响设备行为，修改前请参考技术文档

### 操作后注意

1. **保存文件**：修改后务必点击保存按钮
2. **验证修改**：烧录前建议检查修改后的文件大小是否合理
3. **保留备份**：保存时软件会自动创建 `.backup` 和 `.config_backup-*` 文件，请勿随意删除
4. **配置验证**：保存配置后建议重新加载配置以验证写入是否正确

### 安全注意

1. **仅修改已知资源**：不要随意替换未知类型的资源
2. **配置修改需谨慎**：错误的配置值可能导致设备功能异常或无法启动
3. **谨慎使用覆盖**：覆盖原文件前确保不再需要原文件
4. **配置生成文件检查**：生成的配置文件建议先在测试环境验证后再用于生产
