# Revert 功能测试指南

## 测试步骤

### 1. 基本功能测试

#### 测试 1.1: 替换后恢复
1. 打开一个 RES.BIN 或 DestBin.bin 文件
2. 选择一个资源（例如 ID=10 的图片）
3. 确认 Revert 按钮是**置灰**的 ❌
4. 点击 Replace 按钮，选择一个新文件进行替换
5. 确认 Revert 按钮变为**可用** ✅
6. 点击 Revert 按钮
7. 在确认对话框中点击 "Yes"
8. 验证：
   - ✅ 资源恢复到原始状态
   - ✅ StatusDisplay 显示 "✓ Original"
   - ✅ Revert 按钮再次置灰 ❌
   - ✅ 弹出成功提示消息

#### 测试 1.2: 未修改的资源
1. 选择一个从未被修改过的资源
2. 验证 Revert 按钮是**置灰**的 ❌
3. 点击 Revert 按钮（应该无响应）

#### 测试 1.3: 取消恢复操作
1. 替换一个资源
2. 点击 Revert 按钮
3. 在确认对话框中点击 "No"
4. 验证：
   - ✅ 资源保持修改状态
   - ✅ Revert 按钮仍然可用 ✅
   - ✅ 状态消息显示 "Revert cancelled"

### 2. 多次替换测试

#### 测试 2.1: 多次替换后恢复
1. 选择资源 A
2. 第一次替换：A → B
3. 第二次替换：B → C
4. 第三次替换：C → D
5. 点击 Revert 按钮
6. 验证：
   - ✅ 资源恢复到最原始的 A（不是 C 或 B）
   - ✅ 这是正确的行为

### 3. UI 显示测试

#### 测试 3.1: 工具栏按钮
1. 替换一个资源
2. 检查顶部工具栏：
   - ✅ Revert 按钮可见
   - ✅ 图标显示为 ↩️
   - ✅ 鼠标悬停显示提示文本

#### 测试 3.2: 预览面板按钮
1. 替换一个资源
2. 查看右侧预览面板底部：
   - ✅ Revert 按钮可见
   - ✅ 橙色背景，白色文字
   - ✅ 与 Export 和 Replace 并排显示

### 4. 状态同步测试

#### 测试 4.1: 切换选中资源
1. 替换资源 A（IsModified=true）
2. 切换到资源 B（未修改）
3. 验证 Revert 按钮**置灰** ❌
4. 切换回资源 A
5. 验证 Revert 按钮**可用** ✅

#### 测试 4.2: 保存后状态
1. 替换多个资源
2. 点击 Save 保存文件
3. 验证：
   - ✅ 所有资源的 IsModified 重置为 false
   - ✅ 所有资源的 Revert 按钮都置灰 ❌

### 5. 边界情况测试

#### 测试 5.1: 零大小资源
1. 尝试替换一个 Size=0 的资源
2. 验证：
   - ✅ 显示警告消息 "Resource does not exist"
   - ✅ 无法执行替换
   - ✅ Revert 按钮保持置灰

#### 测试 5.2: 大文件替换
1. 替换一个较大的资源（>1MB）
2. 验证：
   - ✅ 原始数据正确保存
   - ✅ 恢复操作正常工作
   - ✅ 内存占用合理

#### 测试 5.3: 不同资源类型
测试以下类型的资源替换和恢复：
- [ ] JPEG 图片
- [ ] Bitmap 图片
- [ ] WAV 音频
- [ ] Font 字体
- [ ] Binary 二进制
- [ ] Palette 调色板

### 6. 错误处理测试

#### 测试 6.1: 异常情况
1. 替换资源后，手动删除临时文件或破坏数据（如果可能）
2. 尝试恢复
3. 验证：
   - ✅ 显示适当的错误消息
   - ✅ 程序不会崩溃
   - ✅ 状态消息显示错误信息

## 调试技巧

### 查看日志输出

在 Visual Studio 的 Output 窗口中可以看到调试信息：

```
[Revert] Saved original data for logo.bmp, Size=2048
[VM] SelectedResource changed: ID=10, Type=Bitmap, Name=logo.bmp
```

### 常见问题排查

**问题 1**: Revert 按钮始终置灰
- 检查：资源是否真的被修改过（IsModified=true）
- 检查：OriginalData 是否为 null
- 解决：重新替换资源

**问题 2**: 恢复后数据不正确
- 检查：OriginalData 是否在替换前正确保存
- 检查：ResBinWriter.ReplaceResource 是否成功
- 解决：查看错误消息和日志

**问题 3**: 内存占用过高
- 检查：是否有大量大资源被修改
- 检查：恢复后 OriginalData 是否正确清空
- 解决：恢复不必要的资源或保存文件

## 性能测试

### 测试场景

1. **小文件** (< 10KB)
   - 替换和恢复应该在 < 100ms 内完成

2. **中等文件** (10KB - 1MB)
   - 替换和恢复应该在 < 500ms 内完成

3. **大文件** (> 1MB)
   - 替换和恢复应该在 < 2s 内完成
   - 注意内存使用情况

### 内存监控

使用任务管理器监控 ResBinManager.exe 的内存使用：
- 初始状态：~50MB
- 替换 10 个 100KB 资源：~60MB（增加 ~10MB）
- 恢复所有资源后：~50MB（恢复到初始）
